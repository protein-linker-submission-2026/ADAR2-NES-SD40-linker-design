# Structure file conventions

## Naming

- RFdiffusion backbone and Boltz-2 prediction files retain the candidate identifier, target span, design index, and model index wherever the originating stage provides them.
- Candidate-to-backbone mappings and per-model provenance are recorded in the result tables and manifests; filenames alone should not be used as the only provenance source.

## Coordinates and chains

- PDB coordinates are in angstroms.
- Final full-fusion models are stored as chain A unless a stage-specific source file explicitly documents another chain layout.
- The analyzed construct uses ADAR2DD(E488Q), NES, linker, and SD40 in sequence order. Residue boundaries used by each analysis are recorded in the corresponding parameters and RMSD records; do not infer boundaries only from display software defaults.

## Atom and chemistry handling

- RMSD gates use C-alpha atoms for the documented linker residue range.
- Hydrogen atoms are generally absent from RFdiffusion and Boltz-2 protein-coordinate outputs unless explicitly added during docking preparation.
- Docking PDBQT files may include stage-specific protonation, charges, and atom typing generated by the recorded preparation workflow. They must not be treated as chemically identical to the source PDB files.
- Public reference structures retain their original PDB provenance. Waters, ligands, alternate conformations, missing residues, and chain selections are handled according to the stage-specific scripts and logs.

## Interpretation

Predicted coordinates are computational models, not experimentally determined structures. Use the confidence, RMSD, docking, and ranker records together when reviewing a candidate.
