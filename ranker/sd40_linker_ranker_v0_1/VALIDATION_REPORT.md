# SD40 Linker Ranker v0.1 验证与可行性评估

验证日期：2026-09-08  
运行环境：Python 3.11，Linux

## 结论

v0.1 可用于第一轮自动几何排序。代码能正确消除 SD40 整体刚体位姿差异，识别内部形变，惩罚候选非 SD40 部分与 CRBN/PT-179 的严重冲突，并隔离坏文件。它适合作为实验前的“低成本优先级排序器”，但当前证据不足以把总分解释为结合或功能概率，也不应直接设硬淘汰阈值。

## 测试 1：单元与真实结构测试

执行：

```bash
pytest -q
```

结果：

```text
5 passed
```

覆盖内容：

1. Kabsch 对齐能恢复随机刚体旋转和平移。
2. SD40 搜索能处理末端缺失、chain ID 改变和 residue numbering 改变。
3. 无关序列会给出明确错误。
4. 真实 8TNQ 回环得到近零 RMSD、100% 接触恢复、零 clash。
5. 默认过滤启用后，轻度形变通过；重度形变和 24 clash 样例失败。

## 测试 3：确定性复跑

使用同一参考、配置和候选连续运行两次，比较 `ranking.csv` 的 SHA-256。预期与实际均为完全一致。这个测试确认同一输入不会因为随机性导致排名漂移。

## 测试 4：默认过滤逻辑

将 `filters.enabled` 临时设为 `true`，使用默认阈值：

```text
RMSD <= 2.5 Å
contact recovery >= 0.70
clashing atoms <= 10
```

结果：

- `03_mild_deformation`：通过。
- `04_severe_deformation`：因 RMSD 失败。
- `05_artificial_clashes`：因 clash 数失败。

该测试只说明代码正确执行阈值，不说明这些阈值已有实验依据。因此交付配置仍保持 `filters.enabled: false`。

## 可行性判断

### 软件层面：可行

- 输入是标准 PDB 时，批处理流程短、依赖少、结果可复现。
- 序列定位不依赖候选 chain ID 和编号。
- 单个坏文件不会中断整批。
- 计算复杂度对 5–20 个候选很轻；数百个候选也适合串行运行。

### 指标层面：适合初筛，但信息不完全独立

RMSD 与 contact recovery 都在 SD40 对齐后计算，因此相关。contact recovery 增加了界面局部几何信息，但不能视作独立结合能证据。clash 对明显不合理结构有价值，但静态单构象的“无 clash”不是可达性保证。

### 生物学层面：尚未验证

当前没有“模型分数—实验 PT-179 响应”的配对数据，因此不能估计灵敏度、特异度、命中率或最优阈值。真正可行性需要至少把现用 linker 和 5–20 个候选同时预测、评分并实验，之后检查：

1. 现用 linker 在排序中的位置。
2. 单项指标与实验 readout 的 Spearman 相关。
3. Top-N 富集是否超过随机选择。
4. 不同预测 seed/模型之间排名是否稳定。

## 风险与建议

| 风险 | 影响 | 建议 |
|---|---|---|
| 预测模型中 SD40 序列突变或大量缺失 | 定位失败或覆盖率不足 | 查看 errors CSV；必要时单独提供序列变体配置 |
| PDB 含多个相同 SD40 | 自动定位歧义 | 拆分模型或后续增加候选 chain hint |
| linker 只有一个静态构象 | 低估构象空间 | 每条 linker 用多个 seed/模型，汇总中位数与最差值 |
| contact 与 RMSD 权重重复计量 | 总分过度偏向 SD40 几何 | 有实验数据后重新拟合权重，或报告 Pareto 前沿 |
| clash 只用固定距离阈值 | 不区分元素范德华半径 | v0.2 可改为元素半径/软 clash 能量 |
| 没有 AF 置信度 | 低可信结构可能误排高 | v0.2 加 pLDDT/PAE 与多模型一致性 |

## 最终建议

现在可以用它跑第一批，但把 `ranking.csv` 视为实验优先级，而不是结论。第一轮应包含现用 linker 基线、结构多样化的 AI linker，以及少量低分对照；实验数据回来后再决定是否启用自动淘汰和怎样调整权重。
